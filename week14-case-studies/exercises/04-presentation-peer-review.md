# Aşama 4: Sunum ve Akran Değerlendirmesi

**Süre:** ~45 dakika (15 dk sunum + 15 dk soru-cevap + 15 dk yazılı geri bildirim)

---

## 4.1 Sunum yapısı (15 dakika)

| Süre | İçerik |
|---|---|
| 2 dk | İş problemi ve neden bu vakayı seçtiniz |
| 3 dk | Mimari diyagram + 1-2 kritik ADR kararı |
| 7 dk | **Canlı demo** (Aşama 3.4'teki senaryo) |
| 2 dk | Bilinen sınırlamalar + "bir dahaki sefere ne yapardım" |
| 1 dk | Sorulara açık |

## 4.2 Demo canlı çalışmazsa

Bu **olur** ve bu **normaldir**. Hazırlıklı olun:
- Önceden alınmış ekran görüntüleri/kısa ekran kaydı yedek olarak hazır olsun
- "Şu an X hatası alıyorum, beklenen davranış şuydu" demek, hiç demo
  yapmamaktan çok daha değerlidir — hata ayıklama süreciniz bile öğreticidir

## 4.3 Akran değerlendirme formu

Her dinleyici, sunulan proje için şu soruları cevaplar:

| Soru | 1-5 puan | Not |
|---|---|---|
| Mimari kararlar gerekçelendirildi mi? | | |
| Demo, iddia edilen başarı kriterini gösterdi mi? | | |
| Bilinen sınırlamalar dürüstçe paylaşıldı mı? | | |
| Sunum, teknik olmayan biri için de anlaşılır mıydı? | | |

## 4.4 Değerlendirme Rubric'i (Ana README'de detaylı)

Ana [README.md](../README.md#-değerlendirme-rubriği)'deki rubric'e göre
kendi projenizi **önce siz** puanlayın, sonra eğitmenin/akranlarınızın
puanlamasıyla karşılaştırın. Kendi kendini değerlendirme, gerçek dünyada
(performans değerlendirmesi, kod incelemesi) sürekli kullanacağınız bir beceridir.

## 4.5 Geriye dönük bakış (retrospective)

**Görev:** 14 hafta boyunca öğrendiklerinizden, bu projede **doğrudan
kullandığınız** en az 5 kavramı listeleyin (hangi haftadan, ne kullandınız).

Örnek:
> - Hafta 5: Window function ile hareketli ortalama hesapladım
> - Hafta 7: Debezium ile CDC kurdum, REPLICA IDENTITY FULL ayarını hatırladım
> - Hafta 9: A/B test sonucunu yorumlarken p-değeri tuzağına düşmedim
> - Hafta 10: Pipeline'ı Pipeline sınıfıyla kurup sızıntıyı önledim
> - Hafta 12: PII sütunlarını maskelemeyi unutmadım
